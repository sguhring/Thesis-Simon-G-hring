# Which models get volatility right?

Overconfidence in machine-learning and GARCH forecasts of stock return variance.
Master dissertation, Católica Lisbon School of Business & Economics, 2025/26.
Seminar: "Conduct your own end-to-end analytics project" (Nicolò Bertani).

## Structure of the thesis

```
M6 competition ──► model representation ──► M6 replication ──► transfer to VOLARE ──► results
 overconfidence       reimplement 2-4        score vs the         40 US stocks,        which models
 found, models        documented top          163-team             2015-2026, true      under-estimate
 unidentifiable       methods + GARCH,        leaderboard,         realised variance    variance, when
                      HAR, naive, ML          redraw calibration   observed
```

See `DECISIONS.md` for every design choice and its status, and `config.yaml` for the frozen values.

## Pipeline

```
data/raw/volare/*.csv  ─┐
data/raw/yahoo_prices.csv├─► build_panel ─► panel.parquet ─► features ─► features.parquet
data/flags/*.csv       ─┘                                                     │
                                                                              ▼
data/raw/m6/*.csv ─────────────────────────────────────────► models ─► forecasts.parquet
                                                                              │
                                                             scores ◄─────────┘
                                                                │
                                              manuscript/figures, manuscript/tables ─► index.qmd
```

Every model writes the same forecast table (`src/thesis/models/base.py`): one row per asset, origin,
horizon, with variance, return quantiles and M6 quintile probabilities. Scoring reads only that table.

## Setup

```bash
uv venv                                   # or: python -m venv .venv
uv pip install --python .venv -r requirements.txt -e .   # or: .venv\Scripts\pip install ...
```

The notebooks in `notebooks/` use the same environment: in VS Code pick the `.venv` interpreter as the
kernel. If `import matplotlib` fails in a notebook, the selected kernel is a Python without the
requirements; rerun the install line above into it.

Raw data are not in git:

- VOLARE (CC BY 4.0, login): download `realized_variance_stocks.zip` from https://volare.unime.it,
  unzip to `data/raw/volare/realized_variance_stocks.csv`.
- Yahoo prices: `python -m thesis.data.pull_yahoo` writes `data/raw/yahoo_prices.csv`.
- M6 files: `python -m thesis.data.download_m6` fetches `assets_m6.csv` and `submissions.csv` from the
  organisers' repository https://github.com/Mcompetitions/M6-methods.

## Run

```bash
make panel      # data/processed/panel.parquet   (40 stocks x 2,932 days)
make features   # data/processed/features.parquet
make forecasts  # data/processed/forecasts.parquet + realised.parquet: all models, rolling origins (minutes)
make scores     # data/processed/scores*.parquet + manuscript/tables/scores_volare.md
make figures    # manuscript/figures/*.{pdf,png} + manuscript/tables/dm_volare.md
make test       # unit tests: scoring, models, driver (about a minute)
```

On Windows without `make`, call the modules from the venv: `.venv\Scripts\python -m thesis.evaluate.rolling`
(`--models garch,har --symbols AAPL` for a subset; a subset run replaces only those models in the
table) and `.venv\Scripts\python -m thesis.evaluate.run_scores`.

Models live in `src/thesis/models/` (one file each; `MODELS` in `__init__.py` is the registry) and all
return the table described in `models/base.py`. DECISIONS.md entries 10 and 11 state each model's
specification and the forecast schedule (monthly re-estimation, a forecast every trading day). The
pooled LightGBM (`lgbm`, `lgbm_ratio`, each with a `_median` row) is fitted on all stocks at once; the
other models are fitted per stock in parallel.
